Phase B: Three-layer decision system
LAYER 1: SHIPPED
Decision files (JSON)
Curated option space. 6 registries. Growing a decision = JSON edit, not code.
  • archetypes.json: 9 business types (healer · coach · local service · therapist · fitness · salon · restaurant · tradesperson · event producer)
  • palettes.json: 12 curated palettes
  • font-pairs.json: 8 Google Fonts pairs
  • page-layouts.json: layouts for every archetype × page combo
  • widget-registry.json: widget → file + data contract (39 widgets)
  • field-types.json: 21 typed form fields (html_input, sql_type, validation, sanitize)
LAYER 2: SHIPPED
Widgets (EJS + CSS)
39 registered. Unit-tested. Data contracts in widget-registry.json.
  • Shell (5) · Hero (3: centered · split-image · two-col-statement) · CTA (2) · Form (4) · Testimonials (1)
  • Offerings (16): grid-3col · instructor-grid · staff-card-grid · menu-grouped-list · service-menu-priced · pricing-tier-table · weekly-schedule-grid · faq-accordion · reviews-grid · photo-gallery-grid · trust-badges-row · impact-stats-row · credentials-block · hours-location-block · service-area-list · resource-list-card-grid
  • Admin (8): dashboard · crud-list · crud-form · settings-form · quick-links · upcoming-events · tools-row · upload-zone
  • Error + utility (5): 404 · 500 · csrf · icon · stars (+ format-date / upload-zone / cas-reveal / cas-form-validate JS runtimes)
statement-portrait inputs (scaffold_spec answers / _seed_settings): credentials_lines: array of small-caps subtitle lines (e.g. license, location). home_body_blocks: array of paragraph blocks; each entry is either a string (one paragraph) or a nested array of strings (line cluster). statement_cta_text: primary CTA label, default "Text me"; resolves to sms:<digits> when contact_phone is present. Picker honors _harbor_meta.layout_variant_hint='statement-portrait' (bare variant_id matches across every solo-operator archetype) OR mood_keywords containing minimal/spare/quiet. Statement-portrait variants are opt-in: a no-signal scaffold never random-walks into them.
services-page inputs (scaffold_spec answers / _seed_settings, added 2026-05-06): services_intro: optional intro paragraph that replaces the generic "Every engagement is designed around what will actually move the needle." fallback in the /services (and /work-with-me) hero description. Empty/omitted falls through to the default copy. services_image_url: optional URL stamped onto the /services hero image_url; image_alt is auto-derived from site_name. When omitted, the hero block ships with no image_url key (text-only hero). Both flow harbor_to_compose.ts → v1_spec._seed_settings → translate_v1_spec answers → scaffold_spec → spec.pages.services.hero.{description,image_url}. They are page-level data, NOT in the canonical 23 site_settings keys.
