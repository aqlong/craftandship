# /lighthouse/* contrast review (static scan of the markup): 2026-05-27

> **What this is:** a static review of the markup. A script computes contrast ratios from the colors written in `web/views/lighthouse/*.ejs`; no browser, screen reader or other assistive technology was used, and the live axe pass described below never ran. The word "lighthouse" in this file's name and in `scripts/lighthouse_a11y_contrast_scan.py` is the product's `/lighthouse` route (the Harbor companion surface), not Google Lighthouse.

**Parent roadmap item:** `harbor-usability-1-axe-lighthouse-contrast-sweep` (Sub-1 of `harbor-usability-live-browser-followups`).

> **Status at public export:** the table below is the original 2026-05-27 snapshot. Group A (translucent ink on oat) and Group D (copper link) were fixed afterwards: `tests/test_lighthouse_a11y_contrast_scan.py` now pins `ink-faint`, `ink-soft` and `copper-9a5a42` as passing. Groups B (decorative clay/sage/dusk-rose colors) and C (white text on the amber CTA) were not re-verified at export; the scanner still pins those pairings as failing, so treat them as **open**.

**Scope:** every public `/lighthouse/*` route, chat surface (`table`), recall surface (`recall`), template-family picker (`preview`), build-state surface (`lamp/:id`), and the make-public flow (`make-public`, `published`, `cancelled`, `changes-first`).

**Method:** two passes.

1. **Static pairing scan** (this document) - `scripts/lighthouse_a11y_contrast_scan.py` enumerates every distinct foreground/background pairing used in `web/views/lighthouse/*.ejs`, composites translucent colors against their declared paper background, computes the WCAG 2.1 contrast ratio, and asserts pass/fail at AA-normal (4.5:1) or AA-large (3:1). Runs without infra (no DB, no server, no browser).
2. **Live axe-core sweep**, `web/tests/ui/lighthouse-a11y.spec.ts` (Playwright + `@axe-core/playwright`) visits every route against a running dev server with axe instrumentation. Captures contrast violations the static pass cannot see (composited backgrounds with paper-grain radial gradients, hover/focus state, dynamic DOM). **Not run in this pass**, see "Live pass: prerequisites" below.

## Findings: grouped

### Group A: translucent ink text on oat (highest impact)

The Harbor palette defines five graduated ink alphas (`0.45 / 0.5 / 0.55 / 0.68 / 0.7 / 0.85`). Only `0.85` and full opacity pass WCAG AA on the oat background. The 0.45–0.7 band is used pervasively for secondary copy, timestamps, dim helper labels, and rail-flag annotations; all of which fail.

**Recommended fix:** raise the floor for body text to `0.85` (`#5a4f44`-equivalent composite). Reserve `0.45–0.5` for purely decorative non-text use (dividers, drop shadows). The single-line follow-ups under "Bug entries" below break this out per surface so the design pass can be incremental.

### Group B: clay / sage / dusk-rose on oat (decorative-only viable)

`--color-clay`, `--color-clay-deep`, `--color-sage`, and `--color-dusk-rose` all fail AA-large for text on oat. Today they appear primarily on hairline borders + decorative dividers (where contrast isn't a WCAG concern), but a grep should confirm they aren't used as text color anywhere in the lighthouse views. If they are, swap to `ink-brown` for the text and keep the warm color for the surrounding border.

### Group C: white text on lantern-deep amber

`color: #fff` on `#ecbf76` is the failing CTA pattern in `make-public.ejs`. The fix is to flip the text to `ink-brown` (which passes at 7.62:1) and keep the amber fill. The "ink-on-amber" variant is already used elsewhere in the surface, so this is a token-substitution, not a redesign.

### Group D: `copper-a06` on `cream-fdf2e8` (just-fails AA)

4.43:1 vs the 4.5:1 floor, close enough that a small darkening (~`#9a5a42`) clears it without changing the perceived hue. Used for the make-public link accent.

### Group E: passes worth pinning

The lamp / make-public surfaces (`#5a534a` / `#5e4f3a` / `#6e5e48` on warm-cream) all pass comfortably (6.02–7.61:1). These should be the reference pattern for any future Harbor secondary-copy ramp.

## Bug entries

Follow-up items raised by this audit:

- harbor-a11y-ink-faint-on-oat: `--color-ink-faint` (rgba 0.45) and the 0.5 / 0.55 / 0.68 alphas fail WCAG AA on `--color-oat`; raise body-text floor to `0.85` in `web/views/lighthouse/table.ejs` + `recall.ejs` + `preview.ejs`.
- harbor-a11y-ink-soft-secondary-copy: `--color-ink-soft` (0.7) at 4.41:1 fails AA for any text usage; either bump to 0.85 or scope to large-text only.
- harbor-a11y-clay-sage-dusk-rose-text-use: confirm `--color-clay`, `--color-clay-deep`, `--color-sage`, `--color-dusk-rose` are decorative-only across `/lighthouse/*` views (grep + reassign any text usages to `ink-brown`).
- harbor-a11y-white-on-lantern-amber-cta: `color: #fff` on `#ecbf76` fails AA at 1.71:1 in `make-public.ejs` CTA; flip to `ink-brown`.
- harbor-a11y-copper-link-on-cream: `#a06149` link on `#fdf2e8` fails AA at 4.43:1; darken to `#9a5a42` or similar.

## Live pass: prerequisites

The Playwright + axe-core spec at `web/tests/ui/lighthouse-a11y.spec.ts` is wired but not run in this audit because executing it requires:

1. `cd web && npm i -D @axe-core/playwright axe-core` (not yet in `package.json`; held back so this commit does not churn lockfile + CI).
2. A local Postgres with the CAS schema applied.
3. `CAS_HARBOR_ENABLED=true npm run build && npm start` (port 4000).
4. Environment fixtures:
   - `CAS_A11Y_DEV_TRIAL`: UUID of an admin-gated trial keeper (covers `table` / `recall` / `preview`).
   - `CAS_A11Y_LAMP_BUILD_ID`, UUID of a build in `preview` status (covers `lamp/*` / `make-public` / `published` / `cancelled`, note `changes-first` is conditional on `review_status='changes_requested'`; cover it by toggling the column in the test fixture).
5. `cd web && npx playwright test tests/ui/lighthouse-a11y.spec.ts`.

The spec writes per-route raw axe results to `docs/audits/lighthouse-a11y-<date>-<label>.json`. When run, append a "Live pass; results" section to this document mirroring the static table.

## Regression contract

`tests/test_lighthouse_a11y_contrast_scan.py` pins the failing pairings as expected-failing and the passing pairings as expected-passing. A future palette change that fixes one of the failing pairings will fail the test with a diagnostic that names the pairing and points back at this document; the fix-the-doc-too contract.

## Lighthouse score

Google Lighthouse a11y score was **not** captured in this pass; it requires the same running-server prerequisites as the live axe sweep, plus headless Chrome / `chrome-launcher`. The static pass + the wired axe spec together cover the contrast surface the parent roadmap item flagged. Lighthouse-score-only follow-up is tracked separately (the parent `harbor-usability-live-browser-followups` was decomposed precisely because running these end-to-end requires browser + DB + server orchestration that the executor environment cannot provide).
