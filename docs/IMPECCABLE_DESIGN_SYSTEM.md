# Impeccable Design System

> Attribution: the name, and the anti-pattern review that produced the banned list below, come from [Impeccable](https://impeccable.style), a third-party design skill pack for AI coding agents by Paul Bakaus (Apache 2.0). The palette, rules and wording in this document are this project's own; no upstream text is reproduced.

Editorial, restrained, and unmistakably Craft & Ship. This document captures the design
discipline developed during the CAS website redesign (Ocean Blue palette, instrument-serif
italic accents, divided editorial rows) and codifies how to apply the same standard to every
app generated by the CAS build pipeline.

Three parts:
1. **Lessons from the CAS redesign**: what we learned, what we banned, and what replaced it.
2. **Applying the system to generated apps**; how `cli/build.py` and the VISUAL_DESIGN_CHECKLIST
   enforce these lessons at build time.
3. **Roadmap**: the highest-leverage design items still to ship.

---

## 1. Lessons from the CAS redesign

### Palette: Ocean Blue with a single split-complement accent

```
Background     #0C0C0E   (near-black, warm)
Surface-1      #141416   (cards, nav panels)
Surface-2      #1A1A1E   (elevated cards)
Text           #F2EEE5   (warm off-white, not pure white)
Muted          #86868E   (body copy, secondary text)
Dim            #545460   (eyebrows, timestamps, hairline copy)
Primary        #0187a0   (Ocean Blue: the one accent)
Split-comp     #C47A3A   (rare amber warning / highlight)
```

One accent color. Used once per section at most. Everything else lives on a grayscale.
If two things glow, nothing glows.

### The banned list (anti-patterns)

These were found and removed during the redesign. They should never return.

1. **Gradient text on headings.** `text-gradient-vivid`, `bg-clip-text`, violet-to-cyan
   sweeps. A headline is a headline; it doesn't need a rainbow to prove it's important.
   Replaced with: one italic word inside a serif display face, colored `#0187a0`.

2. **Pill-style section eyebrows.** Little rounded badges above H2s with background
   tints and borders. They compete with the heading for attention. Replaced with:
   plain uppercase dim text at 0.75rem, letter-spacing 0.18em, color `#545460`.

3. **Three identical rounded-full icon orbs as bullet points.** When a page lists three
   features, designers reach for three 48px circles with three different colored icons.
   This is a template tell: every generated-app landing page used to do it. Replaced
   with: editorial divided rows (italic serif claim on top, plain-text sub-copy below,
   hairline border-top).

4. **Equal-weight 3-column card grids.** Three cards of the same size, each with the
   same shadow, same padding, same icon. Nothing leads the eye. Replaced with: asymmetric
   2-column grids (one statement, one list of rows) or explicit numbered steps.

5. **Gratuitous glows on non-interactive elements.** A glow is a signal; save it for the
   primary CTA. We killed glows on brand text, on section headers, on inactive cards.

### The editorial divided row (the new workhorse pattern)

This single pattern replaced 80% of the old "feature grid" usages on the CAS site.

```ejs
<div style="padding:1.75rem 0;border-top:1px solid rgba(255,255,255,0.07);">
  <div class="font-display" style="font-size:1.125rem;font-style:italic;color:#F2EEE5;margin-bottom:0.375rem;">
    You describe it.
  </div>
  <p style="font-size:0.85rem;color:#545460;line-height:1.55;margin:0;">
    Plain English. No wireframes, no specs, no technical knowledge required.
  </p>
</div>
```

- Hairline `1px solid rgba(255,255,255,0.07)` border-top: never a full divider.
- `font-display` italic serif for the claim (Instrument Serif in our case).
- `#F2EEE5` text: warm off-white, not pure white.
- `#545460` dim for the sub-copy: secondary on purpose.
- Exactly one accent row per section: swap `color:#F2EEE5` to `color:#0187a0` on the
  **last** item and add a `border-bottom` to close the group.

Three of these rows stacked vertically beat any 3-column icon grid.

### Typography hierarchy

- **Display / Editorial / Brand:** `font-display` → Instrument Serif.
  Used for H1, H2, H3, and emphatic italics inside paragraphs.
- **Body / UI:** default sans → Inter.
- **Heading sizes:** `clamp(2rem, 3.5vw, 2.75rem)` for page H1, line-height 1.08,
  letter-spacing −0.025em. H2 clamps 10–15% smaller.
- **Emotional emphasis pattern:** lowercase italic serif, colored `#0187a0`, set off
  with a comma or line-break. Example: `Your custom web app,<br><em>co-created,</em><br>never just generated.`

### Layout rhythm

- **Section padding:** 6rem vertical on desktop, 4rem on mobile.
- **Max width:** `max-w-site` = 1200px. Hero text caps at 720px. Body prose caps at 640px.
- **Section separators:** `.section-divider` = 1px hairline at 7% opacity, not a shadow, not a gradient.

### Copy voice

- Sentence case, not Title Case. `How it works`, not `How It Works`.
- Periods end sentences, even short ones. `Every app includes.` `Still have questions?`
- No em dashes. Commas or line breaks.
- Active voice. `AI builds it.` not `It is built by AI.`

### Buttons and interaction

- One primary CTA per section. Ocean Blue background, warm off-white text.
- Secondary = ghost (border-only, same warm text).
- Hover: translateY(-1px) + subtle shadow. Never a color shift on the primary, color is the identity.
- No rainbow gradient buttons. Ever.

## 2. Applying the system to generated apps

The CAS build pipeline produces a full working web app from a plain-English description.
The same design discipline applied to the marketing site has to be enforced automatically
at build time, because the customer doesn't see the Tailwind classes; they see the final
page. If the page looks like a template, the craft promise is a lie.

Three mechanisms do the enforcement:

### 2a. `cli/design_data.py`: design context injection

`get_design_context(spec)` merges customer overrides with UUPM defaults and emits a design
brief that's injected into every prompt builder in `cli/build.py` (`_build_explicit_prompt`,
`_build_phase1_prompt`, `_build_phase_n_prompt`).

The brief carries:
- Colors (primary, secondary, accent, on_primary), WCAG AA pre-verified.
- Font pairings from 24 curated sets (no banned fonts; Inter/Roboto/Open Sans/Lato/Arial/Helvetica are substituted with DM Sans/Source Sans 3).
- A style hook from `STYLE_VISUAL_HOOKS` (per-style narrative; modern dark, warm earthy, etc.).
- The `UX_RULES_COMPACT` + `VISUAL_DESIGN_CHECKLIST` string constants (mandatory rules).

### 2b. `VISUAL_DESIGN_CHECKLIST`: mandatory rules

This is a plain-text checklist that reinforces the ~15 high-impact rules Claude tends to
skip. The checklist is injected into the full-mode design context, not the abbreviated
Phase-N context (token budget). After the CAS redesign lessons, four new rules are added:

1. **No 3+ identical rounded-full icon bullets.** Use editorial divided rows (italic serif claim + dim subcopy, hairline border-top) instead.
2. **No gradient text on headings.** Use single-color display text; one italic word in the accent color if emphasis is needed.
3. **No equal-weight 3-column card grids.** Use asymmetric 2-column (statement + rows) or numbered editorial steps.
4. **Section eyebrows must be plain text.** Uppercase, letter-spacing 0.15–0.18em, dim (#545460 on dark, #6B7280 on light). No pill background, no border, no colored tint.

### 2c. Post-processors: deterministic fixes in `cli/build.py`

The prompt tells Claude the rules. Post-processors enforce them even when Claude doesn't
listen. These run after generation and before deploy:

- `_ensure_color_consistency()`: patches CSS custom properties to match spec palette.
- `_ensure_font_loading()`: injects Google Fonts with correct weights.
- `_ensure_nav_glassmorphism()`: applies rgba + backdrop-blur when primary is dark.
- `_fix_admin_dark_stat_cards()`: fixes dark-on-dark contrast failures.
- `_fix_dark_section_text()`: fixes dark text inside dark gradient sections.
- `_ensure_nav_logo()`: wires the real customer logo into the nav, replaces gradient-circle SVG placeholders.

The pattern: **prompt → Claude → post-process → design review → design fix loop.**
Every layer catches what the previous layer missed. The design review agent
(`cli/design_review.py`, Claude Opus) is the last gate; critical issues trigger
`cli/design_fix.py` up to 6 times on prod.

### 2d. What this looks like in a generated app

A generated app landing page should have:
- A single-color serif-italic headline with one accent word.
- Editorial divided rows for feature lists (not icon-orb columns).
- Plain-text eyebrows above H2s.
- An asymmetric 2-column "how it works" section.
- One primary CTA with the spec accent color.
- Glassmorphism nav when the primary palette is dark.
- Warm off-white body text (#F2EEE5 on dark, #1A1A1E on light), not pure white/black.

Any of those missing and the app ships looking like a template. With them, it ships
looking co-created.

## 3. Roadmap (highest-leverage items still to ship)

> None of the five items below shipped: `_strip_banned_tailwind_classes`, `_strip_pill_eyebrow_backgrounds` and the editorial-rows partial do not exist in `cli/`. The v1 pipeline was frozen first, and the v2 compose engine encodes these rules in its widgets instead.

1. **Lint for banned Tailwind classes in generated EJS.**
   Add a post-processor `_strip_banned_tailwind_classes()` that flags `text-gradient-vivid`,
   `bg-clip-text`, `from-violet-*`, `from-cyan-*`, and similar rainbow utilities in generated
   files and replaces them with neutral display classes. Also ban `rounded-full` + `w-12 h-12`
   + `flex items-center justify-center` when three or more appear in the same `<section>`
   (the icon-orb pattern).

2. **Add the editorial divided row to the template library.**
   Put an editorial-rows partial (`views_editorial_rows.ejs`) in the template library and pre-load
   it into `_load_templates()`. Update `_build_design_context()` to reference it by name so
   Claude can `include` the partial instead of reinventing feature grids each time.

3. **Kill pill eyebrows at post-process time.**
   Add `_strip_pill_eyebrow_backgrounds()` that scans `.eyebrow`, `.section-label`,
   `.tag`, and similar classes in generated CSS, removes any `background-color`,
   `border`, or `padding`, and collapses them to the plain-text spec. Complements
   the VISUAL_DESIGN_CHECKLIST rule by enforcing it mechanically.

4. **Swap gallery/dashboard "3 feature card" sections for editorial rows.**
   Update the prompt in `_build_explicit_prompt()` with an explicit NEGATIVE example:
   *"Do NOT emit three equal-size cards in a grid for a feature list. Use three stacked
   rows with `border-top: 1px solid rgba(255,255,255,0.07)` instead."* The model respects
   concrete examples more than abstract rules.

5. **Capture design-review before/after screenshots into `build_logs`.**
   `cli/design_review.py` already runs Playwright. Capture a screenshot at review start
   and after each `design_fix.py` iteration; store them alongside the review issues in
   `builds.design_review_results`. Admins at `/admin/builds/:id` can then visually confirm
   the design system was applied, not just trust the pass/fail score.

---

Ocean Blue, Instrument Serif italic, editorial divided rows, plain-text eyebrows, one
accent per section. That's the system. Everything else is negotiable; those are not.
